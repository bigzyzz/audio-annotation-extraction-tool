# Risk Register

Living register. `project_plan.pdf` Appendix B is the submitted snapshot — this file is the source of truth after that.

PDF numbered risks `R1`–`R9`, which collides with requirement IDs. Living IDs are `RK*`.

## How to use

- Update **in the same PR** as the feature that creates, changes, or closes a risk. Audit Open + High rows in the weekly sprint review (5 min) — per §4.4.1.
- Write new risks as: _Risk of [event] caused by [root cause] resulting in [consequence]_.
- Likelihood / Impact: `L` / `M` / `H` (PDF used 1/3/5/7/9 and %).
- Status: `Open` (PDF: Monitored) · `Triggered` (incident in flight) · `Mitigated` (control in place, watch it) · `Accepted` (we live with it) · `Closed` (PDF: Resolved / Lapsed).
- Tag requirement IDs (R1–R9) in the risk text when it maps.
- Owner = named in Appendix B where one exists; otherwise whoever is closest to the work.
- Triggered → owner runs the **contingency** (Reduction). If that fails a critical milestone → **fallback**.
